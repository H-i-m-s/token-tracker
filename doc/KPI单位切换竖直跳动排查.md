# KPI 单位切换竖直跳动排查

> 记录时间：2026-10-21
> 状态：**竖直跳动已定位并修复**（探针验证：全程字号单值，纵向跨度全 0）。待用户真机确认。
> 本文只记录实测证据与被证伪的假设，不含推测性结论。

## 0. 现象

按用户口述的时间顺序：

1. 换单位（B → M）时，数字与单位之间没有空档，两者紧贴；约 300ms 后才分开到正确位置。「有种变化的时候忘加空格，变完才发现忘加了空格把空格加上的感觉」。
2. 单位横向向右跳；数字也会稍微向上再跳一下。
3. 竖直方向轻微跳动。
4. 从「全部」切到「今日」，切换完毕约 0.3s 后，数字和单位一起往下跳一下，再弹回去。
5. **判据**：从「全部」切到**同样以 B 为单位**的时段不跳；切到**以 M 为单位**的时段跳。
6. 所有时段切换都会跳，「今日」只是举例。

---

## 1. 已修复：横向跳

用户确认「现在确实不水平跳动了」。

**根因**：`settleStripShift`（`ui/kpi-fit.mjs`）对所有宽度变化超过 0.5px 的元素做 340ms 宽度补间，单位元素也在其中。`.tt-unit` 上是 `overflow-y: clip`，按 CSS 规范会把 `overflow-x: visible` 一并变成裁切。窗口还没补宽时窄于 `" M"`（33.75 vs 43.83），前导空格被裁掉，M 贴住数字；补满才露出来，看起来像向右跳开。

**改法**：单位不参与宽度补间，宽度当帧到位。

---

## 1b. 已修复：竖直跳

**触发条件**（用户给出）：只有从「全部历史」切到**单位会变**的时段才跳；切到同样以 B 为单位的时段不跳；其他时段之间随意切换也不跳。

**根因**：`shrinkPrimaryToFit`（`ui/kpi-fit.mjs`）里 `if (cols.length < 2) return;` —— 两列时按比例收字号，单列时直接不收。

时间线（490 宽，全部→近30天，探针实测）：

1. `renderAnalytics` 建好 DOM。此时「今日」列还在（`analytics.mjs:753` 只有 `range === 'all'` 才显示它），`cols.length === 2`。
2. 第一次 `fitKpiCards` 按两列算，两列总宽超界，字号被收到 **14.25px**。
3. `settleTodayTransition` 跑 leave 动画（340ms），「今日」列宽度收到 0，结束后 `display:none`。
4. 动画结束后再算一次：只剩一列，`cols.length < 2` 直接 return，不收，字号弹回 **16.24px**。
5. 屏幕上：切换完成约 0.4s 后，数字和单位一起放大 14%。

**为什么单位变了才跳**：单位从 B（`" B"` 约 32.4px）换成 M（`" M"` 约 43.8px），两列总宽被推过界，收缩量变大，弹回就明显；切到同样以 B 为单位的时段，总宽没变，两层字号几乎相同，所以看不出。

**改法**：退场中的「今日」列（`card` 带 `data-tt-leave`）不参与收缩计算，第一次就算出单列的字号，前后一致。

**机器验证**（`w=490`，`1.23 T` → `628.00 M`，采样到 2s）：

| 指标 | 全程跨度 | 收尾后（>420ms） |
|---|---|---|
| 字号 | 单一值 16.24px | 16.24px |
| 数字顶边 numT | 0 | 0 |
| 数字高 numH | 0 | 0 |
| 单位顶边 unitT | 0 | 0 |
| 整组顶边 strongT | 0 | 0 |
| 带子顶边 beltT | — | 0 |

横向 `numL` 跨度 19.65px，那是「今日」列消失后合计列变宽引起的正常重排；滚动行 `rowT` 跨度 16.24px 是换行滚动本身。

## 2. 竖直跳：录屏证据（已由 §1b 解释）

### 2.1 逐帧扫描方法

两段录屏（20fps）。把每帧压成「每行墨量」曲线，相邻帧之间求最佳 dy（-4..+4）使曲线最吻合；只在横向列段特征一致（内容没变）的帧对之间统计，避免滚动中间态污染。

结果：

| 录屏 | 帧 | dy | 残差 |
|---|---|---|---|
| 第二段 | 42 | −1px | 146 |
| 第二段 | 97 | −1px | 180 |
| 第二段 | 96 | −1px | 270 |
| 第二段 | 153 | −1px | 338 |

### 2.2 稳定段

第二段录屏帧 155–172 共 17 帧，单位字母的上边沿 112、下边沿 154、重心 132.95，**完全不变**。

**这一条与 2.1、与用户观感矛盾。** 20fps 每帧 50ms，若跳动只持续一两帧（60fps 下 16ms），采样会整个跳过。因此「稳定段不动」不能当作「没有跳」的证据。

### 2.3 已测到的量

- 单位横向：换档前后从 `[313-357]` 变为 `[322-371]`，即 B → M 变宽引起的整组居中重排，约 +9px。
- 单位墨迹纵向范围：B 为 39px，M 为 43px。**这 4px 差异属于字形差异，不是字号变化**（B 的上下弧在墨迹边缘比 M 的直边缩进）。

---

## 3. 关键结构事实

- 主卡两列（合计 / 今日）为 `flex: 0 0 auto`，**列宽由内容撑开**。
- `.tt-unit` 宽度由 sizer 决定，换档即变：`" B"` 约 32.4px，`" M"` 约 43.8px，差 11px。
- `shrinkPrimaryToFit` 量**两列实际宽度之和**，超出卡内宽就按比例收字号。
- 由此得到一条完整链路：换单位 → 单位窗口变宽 → 列变宽 → 两列总宽变 → 收缩比例变 → 字号被重新定一次。
- 该链路能解释判据 5（同 B 不跳），但**是否就是竖直跳的原因尚未证实**，见 §4 第 10 行。

## 4. 尝试过的改动

| # | 假设 | 改动 | 结果 |
|---|---|---|---|
| 1 | 单位宽度补间导致空格被裁 | 单位跳过 `glideWidth` | 横向修复，竖直仍在 |
| 2 | 单位位置也需要补 | 新增 `flipUnitPosition` | 无效，已撤回 |
| 3 | 数字宽度补间触发 ResizeObserver，每帧重算字号 | 新增 `animUntil` 守卫 | 竖直仍在 |
| 4 | 动画结束后重算与动画前不一致 | `commitStyles()` 落末值 | 出现「跳一下再弹回」，更糟，已撤 |
| 5 | 合成层销毁导致 1px | `.tt-num-row` 加 `will-change` | 无效 |
| 6 | 同上，层提到父级 | `will-change` 移到 `.tt-num` | 无效 |
| 7 | 同上，动画不撤 | `enterRow` 改 `fill: 'both'` | 无效 |
| 8 | 单位带子 transform 层被回收 | 带子改 `top` 定位 | 无效 |
| 9 | 全线避开合成层 | `.tt-strip`、`.tt-num-row` 改 `top` | 无效 |
| 10 | 单位宽度进 shrink 总宽，字号被重算 | shrink 按档位表最宽档预留 | 无效 |

十轮，零命中。

## 5. 已证伪的假设

1. **「空格被裁」能解释竖直跳** —— 只能解释横向。
2. **「合成层销毁 → 重新光栅化 → 1px」** —— 原理自洽，但改遍三条位移路径（换行、逐位滚、单位带子）均无效；且 §2.2 显示滚动收尾后 17 帧静止。应视为已证伪。
3. **`commitStyles()` 能保住合成层** —— 反而引入往返。
4. **`will-change` 能让层常驻** —— 浏览器会主动丢弃，无效。
5. **「字母墨迹 39 → 43 说明字号变了 10%」** —— 错。同一字号下 B 与 M 的墨迹高度本就不同。

## 7. 尚未排查

1. **60fps 录屏**。当前最大证据缺口：20fps 抓不到一两帧的跳动。两段录屏都在关键处给出「稳定」，与实际观感矛盾。
2. **DevTools Performance 抓一次切换**。确认那 0.3s 前后 `font-size` 被写了几次、Layout 发生几次。
3. **`settleTodayTransition`**（`ui/kpi-fit.mjs`）。它 cancel 动画后会**再跑一次完整的 `fitKpiCards`**，是「切换完毕 0.3s」这个时间点上唯一主动重算的路径。读过代码，未验证。
4. **`unifyLabels` / `unifyRow`**。每次 `fitKpiCards` 都跑，改标签字号会改标签高度，进而推动整组上下移动。只做过逻辑推演，未实测。
5. **`strong` 实际高度是否为整数像素**。若为小数，`align-items: center` 的居中位置落在半像素上，取整不稳定。

---

## 8. 方法上的问题

1. 每一轮都有自洽的机制解释，但没有一轮做过「撤回改动、确认现象是否回来」的对照。
2. 把测量差异直接当成因果（§5 第 5 条）。
3. 在无头浏览器里反复验证 —— 该环境没有真实 GPU 合成，横向宽度与纵向位置能量，合成层相关行为量不到，而这里恰是盲区。
4. 过早锁定单一条件：用户说「只有单位变化才跳」，被读成「且位数不变」，方向走偏一轮。
